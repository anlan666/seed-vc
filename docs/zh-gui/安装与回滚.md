# 简体中文实时变声界面

这是原 `real-time-gui.py` 的中文窗口。实时引擎、检查点参数、MPS/CUDA 选择、`configs/inuse/config.json` 的键，都还是原来的。模型代码没有改。

## 安装

在原来的 seed-vc 目录里操作。启动器已经会把工作目录设到这里，检查点参数也不要改。

1. 确认备份还在。至少留下：
   - 原来的 `real-time-gui.py`
   - 原来的 `configs/inuse/config.json`
2. 把压缩包解压到 seed-vc 目录，让下面两个文件和 `real-time-gui.py` 并列：
   - `real-time-gui-zh.py`
   - `realtime_gui_zh_logic.py`
3. 不要覆盖 `real-time-gui.py`，不要手工改 `configs/inuse/config.json`，不要换检查点。

启动时只把脚本名从 `real-time-gui.py` 换成 `real-time-gui-zh.py`，其它参数保持原样：

```bash
python3.11 real-time-gui-zh.py --checkpoint-path <原来的检查点> --config-path <原来的配置>
```

`--fp16` 和 `--gpu` 如果原来就有，也原样保留。不需要新安装包。用的还是本机已有的 Python 3.11、FreeSimpleGUI、Tk、sounddevice 和带 MPS 的 torch。

## 回滚

把启动命令改回：

```bash
python3.11 real-time-gui.py --checkpoint-path <原来的检查点> --config-path <原来的配置>
```

中文界面可以留着，也可以删掉这两个新文件：

```bash
rm -f real-time-gui-zh.py realtime_gui_zh_logic.py
```

如果在中文界面里点过「开始变声」，配置会被重写，但键和原来一样，旧界面能继续读。想回到点开始之前的那一份，用备份盖回 `configs/inuse/config.json`。

## 界面里会看到什么

- 上方是「开始变声」和「停止变声」。
- 「参考声音」「麦克风」「播放设备」分开写。
- 状态有：正在加载模型、就绪、运行中、已停止、出错。加载失败或启动失败会留在窗口里，并弹出错误文字。
- 「常规参数」和「性能参数」可以折叠。折叠不会停止变声。
- 性能参数一改就会停止，需要再点开始。这和原界面一样。扩散步数和引导强度可以在运行中改。
- 参考路径仍然不能含中文或其它非英文字符。这是原界面的限制。

时间有三个数，都不是麦克风到扬声器的实测端到端延迟：

| 显示 | 含义 |
| --- | --- |
| 算法延迟（估算） | 声卡报告的输出延迟 + 块时长 + 交叉淡化 + 右侧额外时间 + 0.01 秒 |
| 本块处理耗时 | 这一块音频回调的墙钟时间，含语音检测、重采样、模型推理和拼接。原界面把这个数标成 Inference time |
| 其中模型推理 | 只计变声模型那一段。仅监听输入时显示为 — |

块时长需要大于本块处理耗时，否则可能卡顿。这是原来的规则。

## 这次多做的保护

这些是看代码就能确定的问题，不是对那份 Mac 日志的故障结论。

- 刷新设备或停止时，只要音频流还在，就先关掉，再重新初始化 PortAudio。
- 已经在变声时再点「开始变声」，不会再开一条音频流。
- 模型加载失败、参考声音打不开、启动抛错时，窗口还在，并显示中文错误。
- 配置文件能正常读出来时，刷新设备失败不会把它写坏。文件如果本来就损坏，会写成一份带原默认键的 JSON，而不是截成空文件。
- 刷新设备时，如果原来的麦克风和播放设备名字还在，就继续选中它们。

## 日志里实际有的内容

摘录里没有 Traceback。推理循环在继续。不能据此断定用户遇到的故障是什么，这里也没有按某个猜测去改模型或参数。

摘录里看得到的事实：

- 两次 `Using fp16: True`，进程号分别是 19371 和 23288，是两次启动。
- 设备名字都是「外置麦克风」和「Mac mini扬声器」，编号从 1/3 变成 3/5。程序按名字选设备，同名设备换编号可以发生。
- 同一次运行中再次出现 `Input device` 和 `cuda_is_available: False`，说明又走了一次开始变声的日志。摘录没有写出是哪一个控件触发的。
- `IMKCFRunLoopWakeUpReliable` 之后推理还在继续。新界面仍用 Tk，这条 macOS 输入法信息仍可能出现。
- 1454 次 `Infer time`，中位约 0.20 秒，有 4 次大于 0.30 秒的块时长。这只说明偶尔一块比块时长慢，不能单独当成故障原因。

## 这次没有验证的事

开发环境是 Linux，不是那台 Mac。

- 没有跑通 Core Audio、麦克风或扬声器。
- 没有加载 ft1 检查点，没有跑 MPS 推理。
- 没有测量真实的端到端延迟。

- 通过了语法编译，以及 13 个不打开音频、不加载模型的单元测试：配置键往返、事件分类、延迟估算公式、关闭音频流的顺序、布局上的中文按钮和现用参数值。
